# Спецификация v1

Статус: согласованный продуктовый baseline от 2026-10-08. Бета v0.3.0 добавляет JSON; историческая v0.2.0 проверена на трёх комбинациях версий, с русским UI и тестами сбоев/lifecycle; публичный релиз не готов. Технические детали ниже явно разделены на требования и открытые вопросы.

## Результат для пользователя

Администратор WordPress выбирает существующие заявки Forminator, видит состав и предупреждения, получает ZIP с данными и вложениями для дальнейшей работы вне WordPress. Отдельное приложение покупателю не требуется.

Внутри стандартного пакета:

| Объект | Содержание |
|---|---|
| index.html | Общий читаемый индекс с переходами к карточкам и сводкой предупреждений |
| register.csv | Реестр выбранных заявок для работы в таблице |
| data.json | Значения и структура полей, относительные пути вложений, фактический состав и предупреждения |
| Папка каждой заявки | Читаемая HTML-карточка и относящиеся к заявке локальные вложения |
| request.html | Данные заявки, ссылки на вложения и относящиеся к ней предупреждения |

Уточнение от 2026-10-08: JSON входит в стандартный ZIP автоматически вместе с CSV и HTML. XLSX отложен; обратного импорта нет. Контракт JSON описан в [DATA_FORMAT.md](DATA_FORMAT.md).

Колонки CSV, стандартные имена и исследованная модель данных зафиксированы в [описании адаптера](ADAPTER.md). Пакет должен открываться без доступа к исходному сайту; для просмотра HTML и CSV используются обычный браузер и приложение таблиц. Новые имена применяются только внутри архива.

## Обязательные границы

- Только Forminator и уже сохранённые заявки; локальные вложения в первой версии.
- Исходные формы, заявки, имена, пути и байты файлов не изменяются. Удаление нашего плагина не удаляет данные Forminator.
- Никаких импорта, восстановления, миграции, перемещения загрузок или распаковки чужого ZIP на сайт.
- Никаких произвольных путей, серверного файлового менеджера, CRM, кабинетов, облака, AI, расписаний, отправок документов или собственного SaaS.
- Минимальный JavaScript и привычные компоненты админки WordPress; большой SPA-фреймворк не является требованием.
- Защита документов, авторизация и корректная обработка ошибок входят в v1, а не откладываются до релиза.

## Пользовательский маршрут

Одна страница File Packs в админке. Точное положение меню и визуальная компоновка ещё могут уточняться.

| Шаг | Требуемое поведение |
|---|---|
| 1. Форма | Понятный выбор формы; отсутствие форм и отсутствие зависимости объясняются |
| 2. Заявки | Фильтр периода и выбор заявок; дата, ID и краткое представление; видимое количество выбранных |
| 3. Предпросмотр | Число заявок и файлов, оценка объёма при возможности, структура пакета, конкретные пропуски и неподдержанные случаи |
| 4. Сборка | Ясное состояние операции; защита от случайного повторного запуска; достоверные сообщения |
| 5. Результат | Авторизованное скачивание и явный статус полноты; понятное восстановление после ошибки |

## UX-требования

- Первый стандартный экспорт не требует настройки шаблонов, правки PHP или знания модели данных.
- По умолчанию не выбирать скрыто все заявки. «Выбрать страницу» и «выбрать все результаты фильтра», если оба действия доступны, должны различаться явно.
- Объём выбора виден при переходе к предпросмотру. При смене формы несовместимый выбор сбрасывается; изменения фильтра и выбора не должны происходить незаметно.
- Изменение выбора делает прежний предпросмотр неактуальным. Перед сборкой источники перепроверяются; обнаруженные изменения сообщаются в результате.
- Если есть пропуски, пользователь видит конкретные причины до экспорта и может явно продолжить с неполным пакетом. Новые пропуски во время сборки также отражаются в результате и внутри пакета.
- Неполный пакет не получает сообщение о полностью успешном экспорте. Ошибка сборки не маскируется под готовый архив.
- Не показывать выдуманные проценты или время ожидания; если нет измеримого прогресса, показывать состояние операции.
- Длинные значения, Unicode, большие списки и узкие экраны не ломают интерфейс. Не загружать весь список без обоснованных пределов или пагинации.
- Управление доступно с клавиатуры; элементы имеют подписи, сообщения и выбор не передаются только цветом.
- Проверить состояния: зависимость отсутствует, нет форм, нет заявок, пустой выбор, загрузка, предупреждения, сборка, готовый полный/неполный пакет, отказ и повторная попытка.
- UI-тексты переводимы. Набор готовых переводов и окончательные тексты определяются перед релизом.

## Безопасность и целостность

- Проверять серверные права для списка, предпросмотра, сборки и скачивания; nonce не заменяет авторизацию. Матрица ролей определяется по реальным возможностям Forminator.
- Проверять принадлежность заявки форме и файлов заявке. Клиент передаёт идентификаторы, а не произвольные пути или URL.
- Разрешать только подтверждённые локальные источники с проверкой realpath и границ каталога, включая симлинки. Удалённые URL не скачивать.
- HTML-поля экранировать, CSV защищать от формульной инъекции, ZIP-пути и имена нормализовать; совпадающие имена не перезаписывают файлы.
- Сохранять байты разрешённых вложений; не исполнять и не встраивать активные документы в карточки. Исключения по типам должны быть явными.
- Временные пакеты действительно закрыты от HTTP-доступа; случайное имя и .htaccess сами по себе не являются достаточной защитой.
- Выдача авторизована; временные файлы убираются после использования и отказов. Проверить оставшиеся файлы после прерывания запроса.
- Не отправлять заявки и вложения разработчику или платёжному сервису; не добавлять скрытую телеметрию и чувствительные логи.
- Ошибки диска, ZIP-поддержки, времени и памяти сообщаются понятно. Реальные пределы измеряются; универсальные размеры на любом хостинге не обещаются.

## Free, Pro и оплата

- Free — самостоятельный полезный стандартный экспорт, без trial-периода и искусственного счётчика экспортов.
- Будущий Pro — отдельный код вне WordPress.org. Группировка, именование и сохранённые профили остаются кандидатами, а не обещанным набором.
- Lava.top выбрана для коммерческого пути; допустимость товара, выдача ZIP, обновления, возвраты и выплаты ещё не подтверждены.
- Обсуждаемый стартовый формат — разовая покупка с годом обновлений/поддержки, без обязательного автопродления; установленная функциональность не отключается по окончании периода.
- Окончательные цены и состав обслуживания не утверждены. Собственный license server и updater не входят в первый проход.

## Критерий готовности

Первый рабочий результат: пользователь устанавливает ZIP и самостоятельно получает корректный пакет из реальных тестовых заявок через UI. Публичный релиз требует выполнения [чеклиста приёмки](ACCEPTANCE.md), включая безопасность, чистую установку и Plugin Check. Скриншоты или успешная упаковка исходников не заменяют эти проверки.

## Согласованное уточнение от 2026-10-13

Перед экспортом проверять ZIP-модуль и возможность ограниченной записи в закрытое временное хранилище; показывать понятный результат без путей сервера. Пробная запись затрагивает только временное хранилище плагина. Имена скачиваемых ZIP содержат безопасное название формы и дату/время сайта. Быстрые периоды «Последние 7 дней» (включая сегодня) и «Этот месяц» вычисляются сервером по календарю сайта на момент применения. Исправить восстановление после истечения сессии, старые предложения повтора после изменения выбора и устаревшие сводки выбранных заявок. Ограничить ожидание запросов в браузере и разрешить перестать ждать, явно объяснив, что сервер может продолжать работу. Форматы, read-only гарантии для данных Forminator и коммерческие границы сохраняются.


## Согласованное уточнение UX 0.3.4 от 2026-10-13

Индекс ZIP показывает безопасную ограниченную сводку заявки и фактическое число вложений. Интерфейс показывает выбранное количество относительно лимита, следующие шаги для пропусков и отдельную инструкцию после начала скачивания. Допускается хранить только состояние свёрнутой инструкции локально в браузере; отсутствие доступа к storage не мешает экспорту. Единственная форма автоматически выбирается при пустом поиске и отсутствии текущего выбора. Во время сборки/скачивания браузер предупреждает об уходе, если поддерживает beforeunload; это не гарантия сохранения серверной задачи и не предупреждение в простое. Дополнительные форматы и изменение исходных данных не входят в работу.


## Согласованное упрощение UX 0.3.5 от 2026-10-13

Основной маршрут: форма → период → понятный список заявок → «Проверить и скачать» → компактная проверка состава → скачивание. Успешная готовность скрыта, проблемы показываются явно. Инструкция, ограничения, технические форматы, подробный состав и произвольные даты раскрываются по запросу. В списке показывать краткую сводку из сохранённых данных и число сохранённых ссылок на вложения, без обещания их доступности. Проверка ZIP использует фактические проверенные файлы; неполная выдача только по явному согласию. После скачивания объяснить распаковку/index.html и показать схему дальнейшей работы. Предоставить реальные скриншоты с синтетическими понятными заявками, без подмены интерфейса макетом.


## Разрешённое расширение больших выгрузок от 2026-10-14

Убрать фиксированный общий предел количества заявок через сохраняемые задачи и ограниченные самостоятельные ZIP. Добавить явный выбор всех результатов применённого периода, проверяемый прогресс, восстановление страницы, настоящую отмену дальнейшей работы, повторную приватную выдачу и срок хранения. Исходные данные остаются read-only. Внутренние фоновые проходы разрешены; повторяющиеся расписания экспортов, облако и CRM не добавляются. Безлимитные ресурсы хостинга не обещаются. Небольшие выгрузки сохраняют быстрый маршрут с теми же Planner/Package; новый массовый маршрут использует те же проверки источников и формат пакета. См. [архитектуру](LARGE_EXPORTS.md).
